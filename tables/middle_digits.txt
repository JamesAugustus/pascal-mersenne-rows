The middle and nearby entries of Pascal rows
I list the size of the middle entry and whether every entry fits as a single digit in the chosen base.
Pascal rows start with row 0 containing 1; each new row has 1 at both ends and sums neighboring entries inside.
p is the exponent, the base is M_p = 2^p − 1, and the row is n = p+2.
C(n,k) is entry k of row n, counting from 0 on the left.
Read row 4. The list number is 4, p is 7, row n is 9, the second entry is 9 and the third is 36.
Middle position k is 4. Its value 126 takes 7 binary digits (bits) or 3 decimal digits.
The leading value 1.26000000 means 1.26·10^(3−1) = 126; the last 9 digits are 000000126.
Clean is yes because 126 < 127, the base. NO means at least one entry needs a carry into the next place.
For odd n there are two equal middles; I list the left one. Leading values are approximate, last digits exact.
I use the middle, the largest entry, to check whether the entire row fits without carry; this does not test primality.
To generate entries, start R_0 = 1 and use R_(k+1) = R_k·(n−k)/(k+1).
The previous row is C(n−1,k) = C(n,k)·(n−k)/n. End zeros come from paired factors of 2 and 5.
